# Risks

Each risk names what goes wrong, how to detect it, and the control that exists now or is planned.

| ID | Risk | What goes wrong | Detect | Control |
|---|---|---|---|---|
| R-01 | Broker data ≠ LEAN data | Backtest on LEAN or vendor data, trade at a broker with different prices, session times or rollover. The edge only exists in one of the two. | Compare bars from both sources on overlapping days: close diffs, missing bars, spread distribution | Backtest on **broker** data exported to LEAN format (B-14). Source id is in every manifest and run record. |
| R-02 | Timezone and DST | MT5 server time is often UTC+2/+3 with DST. Wrong conversion shifts daily bars, sessions and swap days by hours. | Check bar-count anomalies around DST dates; check weekend gaps start at Friday 21:00/22:00 UTC | Adapter converts with an explicit IANA tz; the tz is stored in the manifest; DST test cases in B-10 |
| R-03 | Spread | Backtests at a fixed or zero spread overstate results, especially for short holding periods and around rollover and news, when spreads widen. | Spread distribution per hour of day from `spread_points` or quotes | Spread is a mandatory assumption in the run record. Stress at 1.5× and 2× (lifecycle stage 3). Risk gate `max_spread_points`. |
| R-04 | Slippage | Market orders fill worse than the quote. Stops slip in fast markets. | Demo fills vs. quote at decision time (`slippage_points`) | Mandatory slippage assumption. Demo stage measures the real value. |
| R-05 | Swap | Overnight financing changes, triple swap on one weekday, and sign or unit differs by broker. Carry-like strategies live or die on it. | Swaps dataset over time | Swaps stored as observed data, never hard-coded. Unit (`swap_mode`) recorded. |
| R-06 | Look-ahead bias | The strategy uses information not available at decision time: bar close used at bar open, revised data, end-of-day values stamped at open. | Code review. Shift test: run with signals delayed one bar; the result should not collapse | Bar time = open-time convention (D-08). The LEAN export writes open times unshifted, which is LEAN's own file convention; a golden test against LEAN sample data guards it (B-14). Review checklist item in AGENTS.md. |
| R-07 | Overfitting and selection bias | Many variants tried, best one reported. In-sample Sharpe means nothing. | Trial count per hypothesis. Probabilistic Sharpe. Degradation from in-sample to OOS. | Lifecycle: frozen design before OOS; OOS touched once; trials counted; LLM-generated variants count as trials too |
| R-08 | Missing or bad data | Gaps, duplicate bars, zero or negative prices, broken OHLC. A gap during a stop-loss move hides a loss. | Adapter checks (OHLC consistency, duplicates). Gap report per partition (B-13). | Ingestion refuses bad rows. `fxra verify` checks checksums. |
| R-09 | Pip / point / lot / contract mismatch | 5-digit vs 4-digit quotes, JPY pairs (3 decimals), lot = 100k units at one broker and something else at another, a min/step of 0.01 vs 0.1. Off by 10× in size or P&L. | Compare `SymbolSpec` to the broker spec and LEAN's symbol properties | `SymbolSpec` per symbol per source, stated explicitly. Risk gate checks volume min/max/step. |
| R-10 | Connection loss | Terminal or VPS disconnects with open positions. Stale quotes look valid. | Quote age and account snapshot age | Risk gate rejects stale quotes and accounts. Every position needs a broker-side stop loss (`require_stop_loss`). Kill switch file. |
| R-11 | Duplicate orders | Retry after a timeout sends the same order twice. A restart replays intents. | Journal of `client_order_id`s. Broker order comment or magic number reconciliation. | Idempotency key per intent. Gate rejects seen ids. Future execution adapter must reconcile with the broker before any retry (B-21). |
| R-12 | LLM-made errors | Plausible but wrong code, invented API behavior, confident claims of edge | Tests, review, run records | LLMs only propose. Human merge. Gates need run records, not prose. |
| R-13 | Memory treated as truth | A Hindsight memory says "Sharpe 2.1" and later work relies on it, but the run was dirty or the number was wrong. | Memories must cite a `run_id` | Rule: numbers come from `run.json` only (D-03) |
| R-14 | Shared server exposure | Hindsight reachable from the Internet leaks the research and lets anyone write memories. | Port scan from outside; `docker inspect` port bindings | Bind 127.0.0.1 + `tailscale serve`, API key, UI key, no funnel |
| R-15 | Two machines write the same data | Conflicting partitions, silent overwrite | Lock files; `fxra verify` | Immutable partitions, one writer host per source (D-09) |
| R-16 | Engine drift | A new LEAN image changes fills or statistics; old results are no longer comparable. | Image digest in every run record | Pinned tag + digest recorded. Bump only by a reviewed commit, and re-run a reference run. |
